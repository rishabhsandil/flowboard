# FlowBoard Code Audit — 2026-05

Audit of the codebase against modern .NET / React best practices. Findings
are split into **fixed in this pass** (already shipped) and **deferred**
(captured for future iterations).

## Fixed in this audit

### Backend
- **Schema integrity**
  - Added `CHECK (status IN ('planned','active','completed'))` on `sprints.status`.
  - Added `idx_issues_assignee_id`, `idx_boards_project_id`, `idx_project_members_user`.
  - All indexes now use `CREATE INDEX IF NOT EXISTS` so the schema is idempotent.
- **Validation at the API edge**
  - `[RegularExpression]` on `Priority`, `SprintStatus`, hex `Color`.
  - `[StringLength]` and `[Range]` on every text/numeric field on Update DTOs.
  - Patterns centralized in `ValidationPatterns` (mirrors Postgres `CHECK`).
- **Error sanitation**
  - `app.UseExceptionHandler(...)` returns `{ error: "internal_error" }` and
    logs via `ILogger`. No stack traces leak to clients.
- **CORS hardened**
  - Replaced `AllowAnyHeader/AllowAnyMethod` with explicit
    `WithHeaders("Content-Type", "Authorization")` and an explicit
    method allowlist.
- **Code organization**
  - Inline SQL in `IssuesController.Create` moved to
    `ProjectQueries.GetFirstColumnId`.
- **Auth**
  - BCrypt cost factor pinned to `workFactor: 12` with rationale comment.

### Frontend
- **Type safety**
  - Eliminated all `catch (err: any)` — replaced with `getApiError(err)` from
    `src/types/api.ts`.
  - `IssueModal.patch()` now takes `IssuePatch` (typed) instead of `any`.
  - `SprintIssue` interface added; `SprintDetailPage` no longer maps
    `(i: any) =>`.
  - Added `vite-env.d.ts` so `import.meta.env.VITE_*` typechecks.
- **UX**
  - All four modals (`IssueModal`, `CreateIssueModal`, `EpicModal`,
    `SprintModal`) now close on Escape via shared `useEscapeKey` hook.

### Documentation
- **`.claude/skills/coding-standards/SKILL.md`** — mandatory rules pack
  loaded before any code edit (auth, validation, Dapper types, error
  handling, query keys, sentinel pattern, modal UX, env access).
- **`CLAUDE.md`** updated with a "Read this first" pointer.

## Verified

### Bug found while writing tests

The original `JwtService.ValidateRefreshToken` looked up
`JwtRegisteredClaimNames.Sub` ("sub") on the validated principal. The
default `JwtSecurityTokenHandler` silently remaps `sub` →
`ClaimTypes.NameIdentifier`, so the lookup returned null and refresh
failed. Fixed by setting `MapInboundClaims = false` on the handler
instance. This is exactly the kind of latent bug the new test project
exists to catch.
